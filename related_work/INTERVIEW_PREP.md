# ⑥ 访谈准备：把客户问题转成可核对的技术问题

**目标：** 对每个问题分清“公开资料已经回答什么、还缺什么、访谈应补什么”。本页是公开资料使用方法和提问模板，不是任何专家的已确认答复，也不收录原始客户表格或完整访谈记录。

## 这次采访 PI，直接用这份

**[PI 专家访谈问卷｜60 分钟：9 个必问＋6 个补充](pi/12_pi_interview_guide.md)**：先沿必问主线了解能力、数据、路线取舍、实际失败与交付；最后用补充池补齐其他需求。提供逐分钟节奏、每题必追一句、可能回答、超时删减顺序和 12 项客户需求覆盖表。

## 每个问题都走这五步

1. **先定义问题。** 例如“泛化好不好”先明确是新家庭、新物体、新任务还是新机器人。
2. **找到公开证据。** 从[八模型表](MODEL_COMPARISON_8.md)和公司入口找答案，再回[原文来源](SOURCES.md)核对。
3. **写清适用范围。** 模型版本、机器人、数据切分、是否适配/人工引导、评价单位。
4. **列出缺口。** 明确哪些字段未披露，哪些只是演示，哪些是你的推断。
5. **把缺口变成追问。** 要流程、定义、样例和量化口径，避免只问“是不是这样”。

## 可直接复用的一行记录

| 字段 | 应该填什么 |
|---|---|
| 客户问题 | 这次真正需要判断的事项 |
| 公开回答 | 一句话结论；没有就填未披露 |
| 来源与位置 | 论文/官方页、日期、章节/图号 |
| 条件和边界 | 版本、本体、任务、样本量、是否适配/干预 |
| 待专家确认 | 公开材料不能确定的具体字段 |
| 期望证据 | 脱敏样例、流程图、统计口径或可复核指标 |
| 访谈后状态 | 公开支持／专家陈述待交叉核验／仍未知 |

## 三个已有学习问题，怎样接到访谈？

先读[数据质量教程](pi/11_data_quality_three_concepts.md)，再使用其中的详细追问。这里保留最核心的问题：

| 主题 | 你先要理解 | 再问专家什么 |
|---|---|---|
| Kinematics sanity check | 实际关节运动是否可信，与时间对齐/延迟不是同一检查 | 查state还是action？阈值依据是什么？异常如何分段与处理？ |
| 多摄像头成功验证 | 画面变化不等于任务成功；判据需结合指令与时序 | 用规则、模型还是人工？怎样标注和处理遮挡？假成功率多少？ |
| 视觉归一化 | 图像格式/尺寸/像素范围与随机颜色增强各有分工 | 具体checkpoint的预处理在哪里？训练和推理怎样保持匹配？ |

**证据归属很重要：** openpi可以核对其公开图像预处理；Gemini的多视角成功检测可以帮助理解技术，但不能自动证明PI采用同一流程。

## 横向访谈的共同问题

| 想了解 | 应先对齐的口径 | 查资料入口 |
|---|---|---|
| 架构优势 | 比较一个动作模型，还是高层+控制器组成的系统？ | [流程比较](COMPARISON.md) |
| 数据规模 | 预训练总量、专项适配量、筛选后可用量分别多少？ | [八模型表](MODEL_COMPARISON_8.md) |
| 泛化能力 | 测试时到底什么没见过？有没有适配或人工指导？ | [八模型表的泛化栏](MODEL_COMPARISON_8.md) |
| 速度和时长 | 单任务耗时、吞吐、推理延迟、控制Hz、累计运行如何区分？ | [调研口径](WORKFLOW.md) |
| 失败与恢复 | 什么算失败？何时人工接管？失败轨迹保留给谁训练？ | [机制路线](MECHANISMS.md) |

## 如何判断本轮已经准备好？

任选一个问题，你能拿出**一个公开结论、一个来源位置、一条边界、一个具体追问**，就已形成可用访谈材料。没有来源的结论保留为待确认，不为了填满表格补猜测。

若接下来做学术实验，再看[研究问题](RESEARCH_QUESTIONS.md)；它与客户访谈是不同产出。
