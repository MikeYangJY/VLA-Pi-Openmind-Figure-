# 技术主线：从“挑技能”到“通用动作模型”

[学习入口](README.md) · [前一篇：零基础分工](00_beginner_map.md)

**这是一条问题演进线，不是说后一项直接加载前一项的全部模型权重。** 读每项只问：过去卡在哪里？现在改了哪里？还有什么没解决？

## 一张表串起来

| 工作 | 要解决的问题 | 核心方法，大白话 | 输出／证据 | 仍然有限制 |
|---|---|---|---|---|
| SayCan，2022 | 大模型说得合理，但机器人不一定做得到 | 用语言模型评估某技能是否有助于目标，再用技能价值函数估计现场是否做得到，结合两者选下一步 | 选择已有技能；看长任务规划与执行 | 依赖已有技能集合，不能仅靠一句话创造任意精细动作 |
| RT-1，2022 | 一任务一策略难扩展 | 用共享 Transformer 从图像历史和指令学习许多任务的动作 | 离散动作；同一策略覆盖大量任务 | 机器人数据中的行为覆盖仍重要 |
| PaLM-E，2023 | 语言模型需要直接理解机器人观察到的场景 | 把图像／状态编码成向量，和文字一起送入语言模型 | 文本推理和计划，再由低层策略执行 | 看懂与规划不等于已经直接学会低层运动 |
| RT-2，2023 | 网络知识怎样直接帮助动作选择 | 机器人动作写成可预测的 token，与互联网视觉语言任务共同微调 VLM | 动作 token 再解码成动作 | 语义组合泛化不等于学会任意全新运动技能 |
| Open X-Embodiment／RT-X，2023 | 每种机器人的数据能否互相帮助 | 汇集多本体数据，训练 RT-1-X／RT-2-X | 多机器人数据带来的正迁移 | 数据格式统一不等于所有身体与动作物理意义完全相同 |
| Gemini Robotics，2025 | 兼顾世界知识、语言跟随与灵巧控制 | 具身推理 ER 与动作 VLA；初代动作系统结合云端与本地 | ER 空间能力、ICL／代码控制、VLA 实机操作分别测 | ER 与 VLA 证据不能混用 |
| Gemini Robotics 1.5 | 动作模型怎样思考、跨身体迁移、完成多步任务 | Thinking VLA + Motion Transfer + ER 编排 | 分别做迁移、thinking、系统组合实验 | 具体训练配方未完整开放 |
| Gemini Robotics 2 系列 | 从桌面双臂扩展到全身与多机器人任务 | 更广的动作能力 + ER 协调 + 本地部署分支 | 官方分任务评测与演示 | 演示不等于工业现场长期无人运行 |

## 1. SayCan：“值得做”与“做得到”一起判断

比如用户说“我把饮料洒了，帮我处理”。语言模型可能觉得“拿海绵”有帮助；但如果没有海绵，或者机器人够不到，它就不该选这步。

```text
任务与已执行步骤 → 语言模型：这个技能对目标有多大帮助？
当前机器人观测 → 技能价值函数：这个技能现在能否成功？
两者结合 → 选一个已有技能 → 执行 → 再选下一步
```

**不要说成：** LLM 自己看相机并输出所有动作；也不要说每个技能必然对应一个独立 BC-Z 模型。核心是语言层选择与可执行性估计的结合。[官方方法图与解释](https://say-can.github.io/)

## 2. RT-1 与 PaLM-E：一个偏动作，一个把感知接入语言推理

**RT-1：** 学“看到这样的画面，听到这样的命令，该怎样动”。官方披露数据超过 13 万条 episode、700 多项任务、13 台机器人、17 个月；实验中已见任务 97%、未见指令 76%。这些是该论文各自测试集合的结果，不能与今天另一套任务直接排名。[RT-1 数据与结果](https://robotics-transformer1.github.io/)

**PaLM-E：** 学“把现场也作为思考依据”。传感器信息编码进语言模型输入，输出仍是自回归文本，机器人示例再连接低层策略。它不是简单把 SayCan 的两个打分器拼起来，也不是 RT-2 式直接预测动作 token。[PaLM-E 方法](https://palm-e.github.io/)

## 3. RT-2 与 π0：都叫 VLA，动作答案可以长得不同

| 比较点 | RT-2 | 原始 π0 |
|---|---|---|
| 借用什么基础能力 | 预训练视觉语言模型 | 预训练视觉语言模型 |
| 动作怎样表示／生成 | 将离散化动作表示为 token，按序预测，再解码 | 专门动作模块用 flow matching 生成连续动作片段 |
| 数据怎样帮助模型 | 共同微调互联网视觉语言任务和机器人轨迹 | 机器人观测、状态、指令和动作片段训练动作能力 |
| 初学者最容易说错 | “它只会说话，不能控制机器人” | “原始 π0 的动作必须先经过 FAST tokenizer” |

这比较的是论文公开的动作路线；**不能反推 Gemini 的闭源动作头一定属于某一种。** Flow matching 不是图片每秒刷新次数；自回归也不会必然把多个正确动作取平均。[RT-2](https://robotics-transformer2.github.io/) · [本库 π0 解释](../pi/01_pi0.md) · [flow matching 从零学](../../openpi_study/07_FLOW_MATCHING_FROM_ZERO.md)

## 4. RT-X：先把“数据集”和“模型”分开

**Open X-Embodiment 是数据集合；RT-1-X／RT-2-X 是用跨机器人数据训练的模型。** 项目页给出 100 万条以上真实机器人轨迹、22 种本体。它证明跨机器人经验有帮助，不证明这套公开数据足以训练今天的所有 Gemini Robotics 能力。[官方数据和模型说明](https://robotics-transformer-x.github.io/)

## 5. 到 Gemini 后，哪些线汇到一起？

此前的三类需求仍在：**理解现场 → 学会动作 → 利用更多来源的数据。** Gemini 的重点是让基础模型知识进入机器人，同时分别处理具身推理、灵巧动作、跨本体迁移和部署。

后续阅读顺序是[初代](01_gemini_robotics.md) → [1.5](02_gemini_robotics_15.md) → [2 系列](03_updates.md)。它们不是“先只有小脑，后来才有大脑”的简单故事；初代已经同时讨论推理与动作。

**自测：** 如果专家说“我们提升了 high-level reasoning，但没有改善 low-level dexterity”，你能解释为什么规划更聪明，手仍然可能抓不稳吗？
