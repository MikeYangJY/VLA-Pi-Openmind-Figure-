# 与 DeepMind 专家沟通：先听懂，再问公开资料没回答的事

[学习入口](README.md) · [公开访谈](09_public_interviews.md) · [来源定位](08_sources.md)

**目标不是让专家再介绍一遍产品，而是请他解释具体选择、失败原因和证据。** 开场先确认对方直接参与的版本、模块和阶段：预训练、ER、VLA、数据、评测还是部署。这样才能分清亲历信息与个人推测。

## 1. 客户问题 → 公开答案 → 真正要追的空白

以下对应已有学习材料中归纳的四项 DeepMind 客户原问题，以及新增的 ICL 问题；编号不代替 Excel 原始行号。

| 客户关心什么 | 公开资料已经告诉我们 | 还值得问的主问题 | 对方这样答时，补哪一句 |
|---|---|---|---|
| 1. 是否仍是 VLA？如何结合 Genie／世界模型？ | 动作模型明确是 VLA；ER 负责推理编排。具体 Genie 联训管线未充分披露。[模型与机制](06_icl_world_models_and_evaluation.md) | **现在最大的能力瓶颈在哪一层？世界模型具体能改善哪一层？** | 若只说“潜力很大”：**已经用于训练、规划还是评测？能举一个实际验证过的例子吗？** |
| 2. RT-X 是否足够？需要什么高质量数据？ | 数据集合与 RT-X 模型应区分；Gemini 有自采多本体和多模态数据。[数据说明](05_training_and_data.md) | **目前最缺哪一类数据？为什么现有数据补不上？** | 若说“需要更多”：**是哪类失败？补数据后哪个指标改善，哪些没改善？** |
| 3. Google 怎样帮助机器人初创公司？ | ER API、VLA tester／合作路径与开发工具是不同入口。[访问与合作](03_updates.md) | **一个新团队从接入模型到首次稳定部署，双方分别负责什么？** | 若只介绍合作项目：**最费时间的是数据、硬件接入、模型适配还是验收？大约哪个阶段最久？** |
| 4. 人员组成、组织管理、营销策略 | 作者／致谢不等于正式组织架构；公开合作名单不等于商业成熟度 | **从模型研发到客户落地，团队怎样分工，市场优先级怎样决定？** | 若只说研究和工程协作：**谁定成功标准、谁收集失败、谁决定模型更新？关键岗位需要什么背景？** |
| 5. ICL 路线怎么看？ | 初代报告有 10 示例 ICL 实验；少样本微调和 ICL 不是一回事。[ICL 证据](06_icl_world_models_and_evaluation.md) | **现在什么问题适合 ICL，什么问题仍必须微调？** | 若说“快速适应”：**参数是否冻结，示范含哪些信息？与同条件微调相比有什么代价？** |

组织与商业问题可以问职责、流程、区间、匿名案例，避免把无法披露的精确数字当成唯一有用答案。

## 2. 顺着专家的回答，追到机制

| 专家常用词 | 你先这样理解 | 一句追问 |
|---|---|---|
| Embodied reasoning | 理解真实空间、时间变化和任务关系 | **改善的是看懂现场，还是最终完成任务？** |
| Orchestrator | 安排下一步并协调工具的模块 | **它收到哪些反馈，何时决定换下一步？** |
| Thinking VLA | 动作模型也先生成推理，再发动作 | **相同任务下，打开 thinking 的收益和延迟各是多少？** |
| Motion Transfer | 从另一种机器人经验中获益 | **目标机器人没见过这个任务，还是完全没进过训练？** |
| Action representation | 模型用什么数字表示动作 | **输出是关节目标、末端位姿，还是其他表示？到控制器前还有什么转换？** |
| Action chunk | 一次生成一小段未来动作 | **实际执行多长就重新观察？突发变化怎么中断？** |
| Affordance | 当前条件下某动作是否做得到 | **可执行性靠学习估计，还是也检查几何和控制约束？** |
| Grounding | 将“那个杯子”对应到真实对象／位置 | **遮挡或多个相似物体时，怎样发现选错了？** |
| Post-training／adaptation | 基座训练后继续适配 | **改变参数吗？适配的是任务、场景还是机器人身体？** |
| Zero-shot／OOD | 某一维度没有见过 | **具体哪个维度没见过？训练中其他相近信息有哪些？** |
| Generalist／specialist | 多任务通用策略／面向某任务的专门策略 | **提高目标任务可靠性时，如何检查其他能力没退化？** |
| Distillation | 用较强模型的信号训练较小／更快模型 | **压缩后损失最多的是哪类能力，怎么测出来？** |

这些是术语解释与建议问题，**不是对 Google 未公开实现的断言**。

## 3. 一小时沟通的逻辑顺序

这是讨论路线，不需要逐字问完整张表。让对方先给具体例子，再进入机制与取舍。

| 时间 | 模块 | 必须带走的答案 |
|---|---|---|
| 0–5 分钟 | 确认经历与一个典型任务 | 他亲自参与什么；任务由哪些模块完成 |
| 5–15 分钟 | 架构与失败 | ER、VLA、控制谁负责；主要失败卡哪里 |
| 15–30 分钟 | 数据与跨本体迁移 | 缺什么数据；如何知道 MT 或新数据有效 |
| 30–40 分钟 | ICL 与世界模型 | 已验证用途、适用边界、还在探索什么 |
| 40–50 分钟 | 合作交付与现场可靠性 | 双方分工、适配成本、验收和人工接管 |
| 50–57 分钟 | 团队与商业优先级 | 职责、人才能力、场景选择及决策方式 |
| 57–60 分钟 | 回收遗漏与确认 | 哪些是实测、哪些是预期；核对最关键结论 |

## 4. 拿到一个数字，立刻补齐六件事

**版本、机器人、任务／场景、是否额外训练、试验次数、成功定义。** 如果谈部署，再问完成时间和人工介入频率。

例如“可靠性 95%”还不够。要补成“哪台机器人、哪类任务、什么变化范围，独立连续执行多少次，是否算入人工恢复”。不必强求一个能涵盖所有任务的公司总成功率。

## 5. 访谈前自测：能答出这些就可以进入讨论

1. **ER 与 VLA 有什么区别？** 一个主要推理／编排，一个直接学习动作；可组合，也有不同接入路径。
2. **ER coding 为什么不是训练？** 它调用现成模型并连接工具，没有更新参数。
3. **Bounding box 为什么不是抓取动作？** 它只是二维位置范围，缺少完整控制所需的信息。
4. **MT 为什么不仅是多加数据？** 报告比较了有／无该配方；但没有公开全部实现。
5. **ICL 与 200 示例适配为什么不同？** 前者推理时用上下文；后者在 On-Device 2 官方说明中涉及训练。
6. **世界模型怎样与 VLA 区分？** 前者预测环境变化，后者选择动作；二者可结合，但要核对实际方法。
7. **为什么 progress 不能当 success？** 完成一部分步骤与完整达成目标不是一个指标。
8. **为什么家庭演示不能证明商业落地？** 还缺长期、重复、低介入和成本方面的证据。
