这里是主线完成后的选读内容；准备客户/专家访谈请去[访谈准备](INTERVIEW_PREP.md)。

以下是本库提出的实验方向，不是对任何团队未公开实现的断言。

| 问题 | 现有工作提供的线索 | 最小可检验假设 | 主要混淆因素 |
|---|---|---|---|
| 动作表示是否损失了接触突变？ | FAST、连续生成模型 | 相同码率下，接触阶段重建误差更能预测任务失败 | 控制器与动作归一化不同 |
| 语义能力为何在动作训练后改变？ | KI 与 Helix 的不同梯度路线 | 隔离梯度在少数据阶段更有益 | 多源 co-training、本体差异和预算 |
| 文本还是 latent 更适合高低层接口？ | π0.5、Gemini、Helix | 文本接口在新约束下更可诊断，但延迟成本更高 | 参数规模、监督质量、下层能力 |
| 记忆怎样避免错误累积？ | MEM 与 agent 成功检测 | 将不确定性与证据来源写入状态可减少错误持久化 | 额外 token 与监督量 |
| 什么时候需要重新生成视觉目标？ | π0.7 与 RTC | 以场景变化触发更新优于固定时间刷新 | 额外计算预算不一致 |
| 自主经验中什么最值得保留？ | RECAP | 中间失败及恢复状态比重复成功更能提升鲁棒性 | 数据总量、纠错质量、价值偏差 |
| 小型在线 RL 的表征瓶颈在哪里？ | RL Token | 接触信息缺失时只更新 actor 难以补救 | 传感器质量、探索和奖励 |
| 人类视频迁移是否依赖机器人基础多样性？ | PI human-to-robot、Figure Index | 机器人数据越多样，新增人类监督越有用 | 场景覆盖与总训练算力共同增加 |

## 如何选第一个问题

优先选择能获得数据、能固定基线、能在现有设备上反复评估的问题。尚无机器人时，先做动作表示或模拟延迟；有可用的动作策略与任务视频后，再研究记忆或编排器。

不建议第一步就尝试从头训练通用 VLA，或者以“复刻闭源旗舰模型”作为无法验收的目标。可以先提出一个窄而明确的问题，用可公开复核的结果证明或推翻假设。

## 提案必须包含

问题与假设；一篇主要对照论文；固定基线；自变量与控制项；任务与数据切分；成功/失败定义；计算与交互预算；预期失败模式；什么结果会让你否定自己的假设。
